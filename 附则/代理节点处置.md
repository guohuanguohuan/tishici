# 代理节点处置（附则；公共规则L13终止线「新规则分流附则」通道，自立锚点NW）

适用范围：凡涉及外网访问的动作（git push/fetch、联网检索、模型 API 等）遇 TLS/握手类断流（schannel handshake fail、unexpected eof、curl 000/502）。本件是附则《故障先修纪律》FX 在网络断流场景的专项化，先修后跑四步（FX-2）同样适用。发现路径：查 `附则/` 目录得见本件。

## NW-1 本机环境事实（2026-09-05 实测，变动即更新本行）
Clash Verge＋mihomo 内核：混合代理口 `127.0.0.1:7897`、控制器 API `127.0.0.1:9097`（凭证 `Authorization: Bearer set-your-secret`）；订阅由 Clash Verge 每 20 分钟自动刷新；**通常挂两个订阅**。主选择器组名随订阅变（实测 `🚀节点选择`／`良心云`）：开工先 GET `/proxies` 列 Selector/URLTest/Fallback，取规则面 github 系域名（DomainKeyword github 在案）指向的 select 组；**禁硬编码组名**。

## NW-2 git 走代理的唯一形态
推送/拉取一律命令行单次注入：`git -c http.proxy=http://127.0.0.1:7897 push origin main`（fetch 同式）。**禁写全局/仓库 config**——节点失效期内直连国内站不受影响，且防止代理配置沉淀成下一轮的新故障源。

## NW-3 节点挑选规则（用户定规 2026-09-05）
①经 API 全量测速：GET `/proxies/{节点名}/delay?timeout=6000&url=https://www.gstatic.com/generate_204`，并发≤8；②**只在日本／美国节点中挑**——取延迟最低者，且须「切换后复测仍活」（探活通过≠数据面通，二者背离实测存在）；③切换：PUT `/proxies/{主选择器}`（JSON body UTF-8 经脚本发送，禁经 bash 命令行带 emoji 明文——实测会编码损坏）；④**TLS 双验才算可用**：`curl -x http://127.0.0.1:7897 https://github.com` 连续两次 200，中间隔 2s；TLS 握手成功但未拿到 HTTP 200 不算通过（ALPN 协商成 h2 时按 HTTP/1.1 发请求会空回，禁误判为可用）。

## NW-4 订阅切换（一个订阅挑不到即换另一个）
触发：当前订阅全量测速日/美节点零健康，或切换后 TLS 双验连败两轮。做法：Clash Verge profiles 目录（`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\profiles\`）内取另一订阅的 YAML，经 PUT `/configs?force=true` 装载后**重新全量测速**（订阅切换后节点名单全变，禁止沿用旧测速结果）。装载失败或另一订阅也不通：按 FX-4 呈报用户（GUI 手动切订阅兜底），禁止硬等。

## NW-5 盯守与上报
推送类任务遇断流不得停等：挂后台看守循环（测速→切换→TLS 双验→推送，间隔≤5 分钟、总帽 3 小时、成功即退出），日志落当轮工作区子文件夹，每轮会话恢复先查看守日志。节点池整体抖动（大面积超时、分钟级死亡）属订阅侧事故，处置经过与教训登记经验件。
