## 多会话并行纪律／工具版本预检（先更后用）／占用预检／工具使用后残留清查（原 L49）

多会话并行纪律（任何多会话组合同时运行时生效；单会话运行时同样执行①的整体提交）：①整体提交——每次提交提示词文件夹整体：不只 add 本会话改动文件，工作区里其他会话与我本人留下的未提交改动（成品、台账、参考文件等）一并纳入提交推送；内容明显异常（空文件、乱码等同步盘损毁特征）的先按§10②处理再入库；②他人文件内容一律不碰——git status、产出文件夹、工作区里的非本单位改动是其他会话的工作痕迹，不 checkout、不恢复、不删除、不当同步盘损毁处理；他人改动只经①入库（只提交、不改动内容）；各线台账与经验文件例外：只写自己单位的行／自己的经验条目；③提交推送前先做并发预检——查 .git/index.lock 是否存在：存在即另一进程正在执行 git 写操作，等其消失（每 30 秒复查）再开始提交推送，禁止删他人锁文件或带锁强行操作；预检通过后推送前 fetch 比对，远程有新提交先 rebase 再推；rebase 被他人未提交改动阻塞等 1-2 分钟重试，仍阻塞按§1处置；④冲突处理——经验积累文件与台账的文本冲突两边条目都保留；docx（转投暂存等）冲突按§9合并规则把两版完整取出合并后继续，禁止丢弃任一边；⑤进程纪律——多会话运行期间禁止 Get-Process 全局杀 WINWORD/Word/PDFCreator 等进程，只允许优雅退出自己启动的 COM 实例（Quit），打印/PDF 导出遇设备占用等 1-2 分钟重试；⑥工作区本轮子文件夹命名必须含「线别＋单位号」（如「同步-物理必修3第12章-0901」），只在自己子文件夹内工作，禁止触碰他人文件夹；⑦git 仓库损坏处置（下条）在多会话期间属全局急停操作——执行前先按§1呈报征询我停止所有会话，处置完 fsck 全绿后再恢复；⑧工具占用与版本预检（通用，单会话同样适用）——**版本预检（先更后用）**：每轮首次使用任一外部软件前先更新至最新版本、再查版本与可运行性并落盘实测值（Word/WPS COM 版本＋开卷冒烟、PDFCreator 打印链路、打印机、TinyTeX/xelatex、Asymptote、Ghostscript、Python 关键库、git——后续新增外部软件〔kimi、node 等〕一律同适用；云模型/应用内嵌模型版本不属本条，模型名以运行时实测值为准）。
更新纪律：①**先查后升**——先经 outdated 类命令查有无新版，有新版才升（升级前落盘当前版本号作回退锚点），无新版＝已最新并落盘；②**更新渠道以官方为准**——包管理器可代管的走包管理器（npm/pip/tlmgr/winget 等，安装来源以实测为准）、GUI 自更新类（Word/WPS/PDFCreator）经官方更新机制查装；③**更新前先过占用预检**——目标软件被占用时按本节占用预检等待纪律处置，被占用不计更新失败；④**失败分类处置**——瞬态失败（网络/超时等）按本节派发/工具失败重试纪律前台重试≥3次，仍失败登记「更新债」入进度看板（区别于工具债；同类未销账只续记一行）后以现可用版本继续；硬阻塞（需重启/管理员权限）与无程序化更新渠道（打印机固件/驱动等）登记原因不硬更、同走「更新债」登记；⑤**更新成功后必复验可运行性**（Python 关键库＝跑代表性工具脚本冒烟，非仅 import 通过），不可运行按本节重试/降级纪律处置、包管理器支持回退的回退锚点版本并登记；⑥**自更新类（kimi/node 等）新版本自下次启动生效**，当轮以运行版本收尾。总纲：仅可更新性失败（非可运行性失败）经登记允许「带旧」开跑——「带病」指不可运行/链路故障，「非最新但可运行且已登记」属带旧、不属带病。落盘记录三段式：更新前版本→更新后版本（或无法更新原因）→复验冒烟结果（瞬态失败含重试次数与最终处置）。同轮复用不重查〔不重更〕；更新成功后必重查；换机/环境修复后先重更再重查；版本不符禁止带病开跑，按本节重试/降级纪律处置。占用预检——使用任何外部程序或系统资源（Word/WPS 等 COM、PDFCreator、打印机、git 写操作等）之前，先查是否已被其他进程占用（进程在运行、文件被锁、index.lock 存在等）：已占用则**一直等待直到释放**——每 30 秒复查，等待期间先推进不依赖该工具的其他工作，无可做就持续等；禁止强杀他人进程（只允许优雅退出自己启动的实例，同⑤）、禁止带锁强行读写。典型场景：docx 被我本人打开锁定时静默等待我关闭；各会话打印任务按§14快照纪律认领各自产物文件、不误拿他人在打印的任务；
⑨工具使用后残留清查（通用，单会话同样适用）——**每次用完任何外部程序或系统资源后，必须清查并清除自己产生的残留才算了结**，四类：进程（自己启动或任务拉起的 Word/WPS、PDFCreator 及其隐藏引擎、python、临时脚本进程等，只结束自己的实例，他人的一律不碰）；临时产物（工作区本轮子文件夹之外的临时文件——PDFCreator Spool 任务件 .pdf 与同名 .inf、spool 目录、导出的临时 PDF/PS 等，只删自己的任务文件）；锁与句柄（确认自己产出的文件已可正常读写、自己之后无 index.lock 等锁残留）；系统状态（默认打印机等被自己临时改动过的须恢复原值）。残留清不掉（文件仍被占用）时按⑧等释放后重删。典型场景：打印到 PDFCreator 后端口监视器拉起隐藏 PDFCreator.exe 持续占用 Spool 任务 PDF——必须先结束该进程再删任务文件；此清查与§10中间文件清理互补（本条管工具进程与工作区外残留），结果记入过程对账。

## git 仓库损坏处置（原 L50）

git 仓库损坏处置（本条用于其他来源损伤）：若 git 报「对象为空、无法读取、bad tree、bad object HEAD」等损坏错误，按序处置：①远端完好时优先外科修复——**首选缺对象回填法**：`git fsck --full` 找出缺失/损坏对象的 sha 与类型 → `git -c http.version=HTTP/1.1 clone --filter=blob:none --no-checkout 仓库URL（见本节提交推送条款） 临时目录`（只拉提交＋树；GB级全量拉取禁令同仓库布局条款）→ 逐颗回填：`git -C 临时目录 cat-file <类型> <sha> | git -C 主库 hash-object -t <类型> -w --stdin` → fsck --full 全绿（dangling 提示无害）→ 删除临时目录。备用：浅克隆 `git -c http.version=HTTP/1.1 clone --depth 1` 到临时目录（网络抖动重试2-3次）→ pack+idx 拷入 .git/objects/pack/ → 删空对象 → `rm .git/index && git reset` 重建索引 → fsck --full 全绿。②同步盘会删除产出文件夹新落地的成品：成品消失先 git status 查删除项，按路径 `git checkout -- <成品路径>` 恢复（并行运行时禁止全仓 checkout，只恢复本单位成品路径）。③repack 条件触发：`git count-objects -v` 显示 loose 对象超 500 个或体积超 50MB 时执行一次 `git repack -a -d`（维护性瘦身）。④仅当云端也损坏或不完整时才从完好工作区重建：删 .git → git init -b main → 配置 user.name=guohuanguohuan、user.email=2812099759@qq.com、http.postBuffer=524288000 → git remote add origin 仓库URL（见本节提交推送条款） → add -A 提交 → 经我同意后 git push -f origin main 修复云端；
重建后按仓库布局条款迁回 git 目录与指针（.git 不得留在提示词文件夹内）。

## 全品对照类轮次流程纪律增补（2026-09-10 体系修订轮；用户明示落库）

- **视觉回归基线制**：每轮改版/修复收尾重渲染全套页图（PNG）作视觉回归基线；像素口径项（字距/标点/版面几何）在源文件重建后必须按新件复测，新旧对照板随报告落盘。
- **可读性打印终检（放行前 100% 打印件目检小字）**：放行前 100% 打印件（或 1:1 打印稿）目检小字可读性——页脚小字、图内标签、题侧括注、表格小字；不符即改、重渲、重检。
- **独立件并行协议**：主管线（正文/版式）串行推进；独立件可并行——TikZ 图重绘、规则修订、独立审计（复审计）互不依赖，可并派并行代理；接口＝落盘文件＋断言脚本，并行件之间禁同文件双写。
- **意见登记册惯例**：每轮用户意见与衍生项逐条登记，五列固定——编号｜来源｜状态｜证据｜处置；编号全轮唯一、状态逐轮闭环，随交付报告落盘。

## 盲态任务纪律（2026-09-14 军师九案落库；轮5 二犯升级触发）

纯盲/半盲类复核补验任务两度因 grep 定位整行回显击穿答案层（路39 O-1、路40 同款复发）。文字纪律独力不足恃，机械化三案并立：

- **d 案·准入制（默认形态，纯盲类必用）**：纯盲任务默认**不下发源件路径**——任务书只 inline 题面（或独立题面文件），臂只回自解；对勘由主脑（或第三臂）机械 diff。臂全程零答案接触，检索无从施展。
- **b 案·固定取行命令**：确须从源件取窗时，任务书给出主脑预生成的取行命令（sed 行号区间直取，行号由主脑核定），臂「只读该命令输出、禁自写任何检索、禁直接打开源件」，命令与输出存档随回执。
- **c 案·盲态纪律块（任务书模板硬条款）**：凡盲态类任务书尾部必附：『禁对源件执行含 `【`/`〔`/`答案`/`详解`/`亲算印证`/`总账` 字样的一切 grep；定位仅限主脑下发命令或 `grep -n '^#\|^##'` 标题行；任何越界即自首并作废重派』。
- **a 案·黑名单句（兜底辅助）**：正文加四词黑名单＋自首条款；单靠文句已两度失效，不作主腿。
- **二犯升级登记**（照 ZH-10⑨d）：轮5 复核路由记「二犯」在案——该路由后续盲态任务强制 d 案准入，不得退回 b/a 形态。
